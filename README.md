# Lead CRM

A lead and opportunity CRM built with React, Express, TypeScript, and MongoDB. Includes scoped reports, activities, email invitations, WhatsApp automation, custom roles, custom fields, lead scoring, and audit history.

## Local setup

1. Install Node.js 24 LTS (minimum supported version: 22.12).
2. Copy `server/.env.example` to `server/.env`. Set `MONGODB_URI` and a random `JWT_SECRET` of at least 32 characters. MongoDB must be a replica set because conversion and pipeline moves use transactions. MongoDB Atlas also works.
3. Run `npm ci`.
4. Run `npm run migrate` to prepare indexes and repair legacy phone and ownership fields. This is rerunnable, never deletes records, and stops if duplicate provider message IDs need manual review.
5. Run `npm run dev` and create the first administrator at `/signup`.

Frontend: `http://localhost:5173`. API: `http://localhost:4000`. Server TypeScript edits reload automatically.

For a local replica set, start MongoDB with `mongod --replSet rs0 --dbpath <your-data-directory>`, then run `rs.initiate()` in `mongosh`. Use `mongodb://127.0.0.1:27017/lead_crm?replicaSet=rs0` as the URI.

`npm run seed` is optional demo setup. **It deletes existing CRM users and records. Use only an empty development database.** Demo administrator: `admin@orbitcrm.test` / `Password123!`.

## Verification

```sh
npm run typecheck
npm test
npm run build
npm run format:check
npm audit
```

Integration tests use an isolated temporary MongoDB replica set, without connecting to `server/.env` or your CRM database. The first run downloads MongoDB; Windows ARM uses the x64 binary through Windows emulation. CI runs the same checks on Node.js 24.

Use `npm run format` to format source. Dependency updates stay within compatible version ranges; major framework upgrades require a separate migration.

## Access and configuration

Administrators manage configuration and all records. Sales managers access their own records and assigned teams; user administration is limited to those teams. Salespeople access their own records. Custom roles can be configured for read or edit access to own or team records. The API enforces permissions on list filters, conversions, pipeline moves, related activities, and notes.

New leads and opportunities default to the creator as owner. CSV imports belong to the importer unless an assignment workflow changes ownership. The migration assigns existing ownerless records to their active creator.

Configuration includes custom fields, scoring rules, and audit history. Custom fields are validated on the server; lead and opportunity forms render active fields. Active rules calculate scores shown in the lead list. CSV imports support standard lead fields; imports with required custom fields are rejected with an explanation.

Pipeline totals include all matching records, with a Load more button for additional cards. Reports respect access, resolve names, and average probabilities as percentages. Audit records are generated by the system and cannot be changed or deleted through the API.

## Email invitations

Configure `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM`, and `APP_URL` in `server/.env`. As an administrator, open Configuration > Users > Invite person. Invitation links are single-use; recipients set their passwords. Production `APP_URL` must be the public HTTPS URL.

## WhatsApp delivery and recovery

Configure WhatsApp variables from `server/.env.example`. Meta webhook URL: `/api/webhooks/whatsapp`. Signed payloads are stored before returning 200. Indexed normalized phones and a unique provider/message index prevent concurrent duplicate message records.

Local servers recover queued jobs every 15 seconds. **Hosted/serverless deployments need a scheduler** to call `GET /api/internal/whatsapp-jobs` every minute with `Authorization: Bearer <CRON_SECRET>`. Set a random `CRON_SECRET` in the hosting environment. Each run handles up to ten jobs; failures retry with backoff, up to five attempts. Failed jobs remain in `webhookjobs` with their error and payload; completed jobs expire after 30 days.

If processing a bot reply is interrupted, recovery hands the conversation to a person rather than repeating an uncertain send. External message delivery and database writes cannot form one transaction.

## Deployment

Run `npm run migrate` against the intended deployment database before releasing this version. Production disables automatic index creation, so migrations are required. Build with `npm run build`; the existing `vercel.json` handles the frontend and serverless API. The Vercel CLI is no longer a project dependency; install it separately if needed. Configure hosting secrets and the recovery scheduler above.

## Import review and workflow ordering

CSV import rejects repeated column headings, mismatched column counts, and unclosed quotes before review. Quoted commas, multiline notes, and UTF-8 BOM files are supported. Automatic mapping uses each CRM field once. Review shows row-level reasons and downloadable reports; invalid rows do not prevent a later valid row for the same contact from being imported. Error exports neutralize spreadsheet formulas. The demo dataset includes international phones, multiline notes, and a zero-value pilot.

Workflow steps can be moved up or down before saving. Their displayed order is their execution order; place ownership assignment before owner notifications or follow-up creation when those steps should use the new owner.
